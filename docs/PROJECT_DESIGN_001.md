## 三、核心问题与知识点对应

### 3.1 核心问题

**一句话**：学生看到「准确率 99%」就认为模型很好，却分不清「同一个指标在训练集与验证集上的差距」和「整体指标掩盖了少数类完全失效」；系统给出的反馈也无法指向学生原话中的哪一句触发判断。

模板用「过拟合」场景（训练 99% vs 验证 78%，**同一指标的两个数据集**），本组换为「类别不平衡」场景（整体准确率 99.2% vs 少数类召回 8%，**一个整体指标掩盖了一类样本**），教学价值在于逼迫学生区分「泛化不足」与「评价指标选错」这两种性质完全不同的问题。

**问题拆解**

| 维度 | 现状痛点 | 本组目标状态 |
|---|---|---|
| 学生侧 | 只得到对/错，不知道缺的是概念、证据还是行动 | 四维分级提示，明确指出缺失维度 |
| 教师侧 | 反馈与回答的关联不可见 | 每条记录含命中的**原文片段与位置** |
| 系统侧 | 只有来源标记，无法回溯到具体语句 | `evidenceSpans` 逐条指回原句 |

### 3.2 知识点映射

| 课程知识点 | 本组落点 | 可观察证据 |
|---|---|---|
| LLM 与 Prompt | 四档反馈模板的分层设计 | `feedback` 分支代码 |
| Tools / 确定性计算 | 规则引擎承担判定，不让模型「猜」 | `analyse()` 四维匹配 |
| Knowledge / 可追溯知识源 | 错因分类表 + `knowledgeRef` 字段 | `knowledge/misconceptions.json` |
| State / 状态管理 | 会话记录、上限 100 条、可清空 | `saveEvidence()` |
| Evaluation | 正常/异常/边界/回归四类测试 | 测试表 T01—T06 |
| Agent 编排边界 | 系统不自动评级，教师保留裁决权 | 教师视图 + 文档声明 |

### 3.3 诚实性声明（不可省略）

当前基线判定模式为 `rule_baseline`，**不调用任何大模型**。报告与答辩中不得表述为「由模型完成诊断」。
若后续引入模型（L4），必须补充「模型输出如何被规则校验」与「密钥如何管理」，否则不予评分。

## 四、本组项目定义

| 项 | 内容 |
|---|---|
| 选题方向 | 教育智能体（对应课程模板 3.1 节第一个方向） |
| 自拟名称 | MindTrace-Skew |
| 演示场景 | CASE 002：信用卡欺诈检测，样本 99:1，整体准确率 99.2%，欺诈召回仅 8% |
| 目标用户 | 学习机器学习基础课的本科生；教师作为复核者 |
| 最小可运行功能 | 学生提交解释 → 四维诊断 → 带原文定位的分档反馈 → 教师查看证据与分布 |
| 本组贡献 | 场景重构 + 证据定位 + 四维分档 + 教师统计（详见第五章） |

**CASE 002 题面（替换模板 CASE 001）**

> 你训练的信用卡欺诈检测模型整体准确率 99.2%，但在测试集里 100 笔真实欺诈交易只识别出 8 笔。你认为发生了什么？如何确认并改进？

**三个指标卡**

| 指标 | 值 |
|---|---|
| OVERALL ACCURACY | 99.2% |
| FRAUD RECALL | 8% |
| CLASS RATIO | 99 : 1 |

> 与模板的关键差别：模板是「训练 99% vs 验证 78%」——**同一指标在两个数据集上的落差，指向过拟合**；本组是「整体准确率 99.2% vs 少数类召回 8%」——**一个看似很好的整体指标掩盖了一类样本的完全失效，指向类别不平衡与指标选择错误**。两者结论不同，改进手段也不同。

### 5.2 本组三项必做增量

**D1 场景替换（CASE 001 → CASE 002）**

- 把「过拟合」换成「类别不平衡 / 准确率悖论」
- 词表从 3 组扩为 4 组，新增「不平衡 / 少数类 / 召回 / 精确率 / F1 / 重采样 / 类别权重 / 混淆矩阵」等
- 价值：强制重写核心逻辑，天然规避雷同；且两场景易混淆（都是「指标看起来不对」），有真实教学价值

**D2 证据定位字段 `evidenceSpans`**

```ts
export type Dimension = 'concept' | 'evidence' | 'action' | 'verification'

export type EvidenceSpan = {
  dimension: Dimension
  matched: string   // 命中的原文片段
  start: number     // 在原回答中的起始下标
  end: number       // 结束下标（不含）
}
```

- 反馈面板展示「你的这句话触发了该判断」
- 价值：把「可追溯」从「有来源标记」提升到「能指到原句」，这是模板没有的能力

**D3 第四维「验证方案」与分档细化**

| 档位 | 判定条件 | 结论示例 |
|---|---|---|
| 1 | 未提及少数类或召回 | 尚未识别多数类与少数类的表现差异 |
| 2 | 指出整体准确率高但少数类表现差 | 已注意到整体准确率掩盖了少数类失效 |
| 3 | 命名「类别不平衡 / 准确率悖论」 | 已识别类别不平衡问题 |
| 4 | 命名原因 **且** 给出可检验改进 | 已识别原因并给出可验证的改进方案 |

- 新增 `verification` 维度词表：「重采样」「过采样」「欠采样」「类别权重」「阈值调整」「F1」「PR-AUC」「分层交叉验证」「混淆矩阵」「少数类单独评估」
- 价值：区分「给结论」与「给可检验方案」，这是模板 3 档做不到的

### 5.3 选做增量（不加分，用于答辩加分陈述）

| 编号 | 内容 |
|---|---|
| D4 | 错因分类表外置为 `knowledge/misconceptions.json`，含来源与版本字段 |

## 七、操作流程

**学生侧（6 步）**

1. 打开 `http://127.0.0.1:5173/`，阅读 CASE 002 与三指标
2. 选择演示身份（学生 A / 学生 B）
3. 写下对「整体准确率 99.2% 但欺诈只识别出 8%」的解释
4. 提交，获得档位结论与建议
5. 查看「命中原文」区块，确认系统指出的句子确实是自己写的
6. 查看个人会话记录

**教师侧（4 步）**

1. 切换到教师证据视图
2. 按学生分组查看：时间 / 原回答 / 档位 / 反馈 / 模式 / 来源
3. 查看四档分布统计（D5）
4. 必要时清空本地演示记录

**异常路径**

| 场景 | 期望行为 |
|---|---|
| 空输入 | 提示「请先填写回答」，不产生记录 |
| localStorage 损坏 | `getEvidence()` 返回空数组，页面不崩溃 |
| 回答无任何命中 | 落到第 1 档，`evidenceSpans` 为空但不报错 |

## 十二、常见实现风险

| # | 风险 | 现象 | 后果 | 规避 |
|---|---|---|---|---|
| 1 | 与模板雷同 | 题干、词表、文案仍是模板原样 | 判定抄袭，独立贡献度归零 | 按 2.2/2.3 逐项核对后再提交 |
| 2 | 只换皮不改逻辑 | 改了颜色和标题就算完成 | 核心分丢失 | `git diff` 自查变更行占比 |
| 3 | 换场景后知识点脱节 | CASE 002 与课程内容对不上 | 报告逻辑断裂 | 保留「同指标跨数据集差距 vs 整体指标掩盖少数类」对照说明 |
| 4 | 否定句误判 | 「不是类别不平衡」被判为已识别 | 诊断错误，证据失效 | 增加否定窗口检测，写 S5 用例 |
| 5 | 位置偏移 | `start/end` 与实际片段不符 | 证据链失效 | 用 `slice` 断言固化 |
| 6 | 档位判定过粗 | 4 档实际只有 2 档可达 | 分档设计失效 | 用 S1/S2/S3 三例验证档位跨度 |
| 7 | 技术栈膨胀 | 中途引入 RAG、多 Agent | 做不完 | 锁定 MVP 边界 |
| 8 | localStorage 当数据库 | 换设备数据全丢 | 演示翻车 | 报告明确「仅本机浏览器」 |
| 9 | 夸大能力 | 写成「模型自动诊断」 | 违反诚信要求 | 统一标注 `rule_baseline` |
| 10 | 密钥泄露 | API Key 写进代码 | 安全零分 | 走环境变量，`.gitignore` 排除 |

## 十三、难度控制

**为什么「准确但不复杂」**

- 业务代码集中在 `adapters/learning.ts` 单文件，学生一节课可通读
- 无后端、无数据库、无网络请求，排除环境变量
- 判定是正则匹配，可完全掌握并自主修改
- 但概念密度不低：契约设计、四维分档、证据定位、否定句边界、人机分工，都是 AI 应用工程的真问题

**增量难度递进**

| 层级 | 内容 | 要求 |
|---|---|---|
| L1 | D1 场景替换 + D3 四档分档 | 必做 |
| L2 | D2 `evidenceSpans` 定位 + 否定句处理 | 必做 |
| L3 | D4 知识表外置 / D5 教师分布统计 | 选做 |
| L4 | 接入模型生成反馈，规则做结果校验 | 需教师批准 |

L4 之所以需批准：一旦引入模型，必须回答「幻觉如何拦截」「密钥如何管理」，否则触碰课程模板 2.4 节红线。
