# 方案 002 · MindTrace-Bayes（当前实现）

> 本文件记录**现行**实现方向。`docs/PROJECT_DESIGN_001.md` 记录的「规则引擎 + 四维词表」方案已被整体替换，仅作历史留档。

## 一、方向变更的理由

方案 001（MindTrace-Skew）的核心是**手工四维词表 + `if (hasConcept && hasPlan)` 布尔判定**。实测后暴露三个结构性问题：

1. **判定依据来自开发者**：`MC-IMB-02` 这类知识编号在代码里没有任何出处，「可追溯」是形式上的。
2. **无法评估**：规则没有准确率概念，只能说「符合预期」，不能说「好到什么程度」。
3. **扩展要改代码**：想识别新的表达方式，必须改词表并重新阅读逻辑。

方案 002 把这三点的根都换掉：判定由**标注样本训练出的概率模型**给出，因此可评估、可由数据驱动、可解释到特征级。

## 二、核心机制

```
回答文本
  → extractFeatures()   字符 bigram + 英文 token + 数字 + 否定标记
  → 伯努利朴素贝叶斯     P(c) × Π P(f|c)
  → 温度缩放 softmax     让概率反映真实不确定性
  → 四类概率 + 逐特征贡献
```

### 与方案 001 的对照

| 维度 | 001 规则引擎 | 002 朴素贝叶斯 |
|---|---|---|
| 判定依据 | 开发者写的词表 | 32 条标注样本的统计分布 |
| 输出 | 单一档位 LEVEL 1—4 | 四类概率分布 + 最高类 |
| 可解释性 | 命中片段 | 逐特征贡献（有正负方向） |
| 可评估性 | 无 | 留一准确率 87.5% + 混淆矩阵 |
| 扩展方式 | 改代码 | 加标注 |
| 处理否定 | 前缀窗口 + 转折词白名单 | 否定词生成独立特征（不跨标点） |

## 四、关键参数（均由实验确定，非拍脑袋）

| 参数 | 取值 | 依据 |
|---|---|---|
| 变体 | `bernoulli` | 多项模型在本场景（小样本、短文本）存在长度偏置：未匹配的特征不扣分，导致系统性地偏向「词典外」的类，实测准确率为 0 |
| 平滑 α | 0.05 | α ∈ [0.01, 0.10] 时准确率稳定在 84.4%—87.5%，取中段 |
| 温度 T | 5 | 留一 log loss 最小（0.583；T=1 时为 0.814，softmax 饱和成 0%/100%） |
| 训练集规模 | 32 条（每类 8） | 句长均衡后准确率由 75% 提升到 87.5%，说明长度偏差修正比增加样本更有效 |

## 五、评估结果（留一交叉验证）

```
混淆矩阵（行=实际，列=预测）
        L1  L2  L3  L4
   L1    8   0   0   0
   L2    0   6   2   0
   L3    0   1   6   1
   L4    0   0   0   8

准确率 = 28 / 32 = 87.5%（随机基线 25%）
```

错误集中在 L2↔L3、L3↔L4 的边界，属于口径本身模糊（「描述了现象但没命名」与「命名了但不给方案」），不是实现缺陷。

## 六、必须同时声明的局限

1. **训练集是自拟的 32 条**，不是真实学生作答，不能外推为「本模型能准确判定真实学生」。
2. **字符 bigram 不分词**，会切出「别不」这类无意义组合；换来的是零依赖、可离线。
3. **词袋模型忽略语序**，「不平衡不是类别问题」与「类别不平衡」的区分能力有限。
4. 概率经温度缩放后仍偏自信，页面标注了准确率与样本量，读者应据此判断。
